# 设计稿：影之刃零 Boss Rush Mod

状态：草案，待确认。数据来自游戏资源扫描（Steam build，PBZ.exe CL-302256），带 ⚠ 的部分要等探测 mod 在游戏里实测后才能确认。

## 1. 名字

- 项目、发布名：**Boss Rush**。发布标题带上搜索词：`Boss Rush — 影之刃零 / Phantom Blade Zero（首领连战 · 复战 · Rogue）`。
- 游戏里不出现 “Boss Rush”，所有游戏内用词都按原作风格来写，见 [COPY.md](COPY.md)：入口叫「强敌挑战 / Boss Challenge」，三种玩法分别是「单挑」「连战」「试炼」。

## 2. 交互原则

1. **手柄能走完全程。** 只用游戏自己的 UI 和交互，它们本来就支持手柄：确认、返回、方向键、摇杆切换选项，按钮提示自动跟随设备显示 Xbox、PS 或键鼠图标。
2. **不需要任何专用按键。** 键盘快捷键只给开发调试用，默认关闭。
3. **进出口统一在铃铛。** 铃铛是游戏的存档点（路角铃铛），玩家本来就会在这里休整，所以在这里开始、结束和返回最自然。

## 3. 入口：铃铛菜单（推荐）

资源里能找到：铃铛菜单 `UI/InGame/Bell/W_BellMenu`，以及推出铃铛菜单的 `AnimNotify_PushBellUI`。

（已定）做法是在铃铛菜单的选项列表末尾注入一个新条目「强敌挑战」，选中后进入我们的流程。铃铛菜单原有的功能完全不动。

备选入口：在铃铛旁边生成一个 NPC，比如复用游戏里已有的 NPC 模型，走过去按交互键对话。代入感更强，但要处理模型、站位和交互提示，而且每个铃铛都要找到合适的站位，工作量大得多。可以作为第二版加上，第一版先只做铃铛菜单。

⚠ 需要实测：铃铛菜单的选项是写死的，还是从数据表生成的。如果是数据表，注入会很干净；如果是写死的，就改为在打开铃铛菜单时额外弹出一个“强敌挑战”入口按钮，或者退回 NPC 方案。

## 4. 菜单与选择：复用游戏的对话选项

| 用途 | 复用的游戏 UI |
|---|---|
| 所有多选一：选玩法、选关卡、选难度、Rogue 三选一之门、心法三选一 | 对话框 `WBP_FlowDialog` + 选项按钮 `W_DialogueButton` |
| 确认和警告（开始挑战、放弃挑战） | `UI/Foundation/Dialogs/W_ConfirmationDialog` |
| 轻提示（第 3/6 战、获得心法、禁制生效） | `WBP_FlowTips` |
| 首领击败 | 游戏原生的 `W_BossDead` 横幅照常出现 |

对话框可以显示一行“说话人”和一段正文，比如由“擂主”介绍规则，选项就是按钮。这是武侠里很自然的呈现方式，手柄上下移动、确认选择即可。

禁制是多选，用对话选项表示为“开关列表”：每个禁制一行，行尾显示 ✓ 或 ✗ 和当前难度分，选中就切换开关，最后一行是“开始”。

⚠ 需要实测：能否从 Lua 构造这个对话框并填入任意文字和选项。如果不行，退路是用 UE4SS 创建一个简单的 UMG 列表控件，用游戏的焦点导航来支持手柄，外观比原生 UI 朴素。

## 5. 流程

```
铃铛 → [强敌挑战]
  ├ 单挑→ 选首领（只列出打过的，分页，每页 6 个）→ 选难度（入阵 / 破局 / 逆天）→ 确认 → 开战
  ├ 连战 → 选关卡（显示首领数、最佳用时、是否通关）→ 禁制开关列表 → 开始 → 连续作战
  ├ 试炼 → 确认开局 → 战斗 → 三选一之门 → 心法三选一 → … → 结算
  ├ 战绩（各关最佳用时、Rogue 最远层数）
  └ 离开
战斗中：暂停菜单里多出「放弃挑战」（⚠ 能注入就加，不能就用“死亡即结束”）。
结束（胜、负、放弃）→ 结算对话框 → 自动传送回出发的铃铛，并恢复进入前的血量和道具。
```

**战斗场地：「择地」**（第二次修改：镜花水月偏暗，不再作为唯一场地）

选完模式之后、开战之前，多出一步「择地」，用和原作铃铛传送地图一样的列表加缩略图（缩略图直接用 `DT_BellData.BellTexture`）。可选项：

| 选项 | 内容 | 什么时候能选 | 代价 |
|---|---|---|---|
| **原址** | 首领当初的战场。只出现在「单挑」里，目前只有彭猛、横刀客、风雪刀客 | 该首领已击败 | 跨地图时要加载一次 |
| **名胜 ×6** | §5.0 表中第 1–6 处（默认选第一个已解锁的） | 对应铃铛已激活（与“只含打过的首领”同一套规则） | 跨地图时要加载一次 |
| **镜花水月** | 保留，供喜欢这种氛围的玩家选 | 始终可选 | 同一张地图内，不用加载 |

**定稿（用户确认）**：场地就用 §5.0 这 8 处，「就地」取消，其他场地以后有需要再加。

- **一局只加载一次**：连战和试炼整局都在同一处场地打，场与场之间不换地图。
- **跨地图传送**：用原作的 `UPBZSaveLoadSubsystem::TeleportTo(LevelName, Transform, BellID)`。铃铛坐标从 `DT_BellData` 离线解析得到（187 条，见 `src/data/bells.tsv`）；游戏内的 `BellManager` 查询函数返回为空，不能用。结束后回到出发的铃铛。
- **跨地图传送已实测（第 12 轮）**：`TeleportTo(FName("/Game/Maps/B02/PBZ_Xigu_WP"), 变换, FName("Bell_NLES_023"))`，地图名用完整路径，铃铛 ID 加 `Bell_` 前缀。6 处名胜都精确落在标点上（误差不超过 4 cm），也能传回出发点。
- **不调天时**：用户决定沿用游戏默认的时间和天气。（实测 F3 改 `Time of Day` 也没有画面变化。）
- **原址**：优先用「打完首领才出现的铃铛」作为原址的传送点，见下文 §5.1。

**暂定范围（用户决定）**：上表中依赖场景点位的首领**暂不开放**，以后补点方案做好再加。另外，血量到 0 后必须重击处决才会死的首领（实测彭猛；它的「假死」开关本来就是关的，是别的机制）：先测在血量到 0 时调用游戏的 `Kill`，若无效，这类首领也暂不开放。

处理办法（按优先级）：
1. **原址**：原关卡里这些点都在，最稳。
2. **在新场地补点**：这些辅助点大多只有一个场景根节点（例如 `BP_ChangHong_RunPoint` 里只有 `DefaultSceneRoot`）。开战前由 mod 在场地上按相对位置生成同类的点（中心点放在场地中心，落点、召唤点放在两侧），技能用 `GetActorOfClass` 就能找到。相对位置最好照搬原关卡的摆放。
3. **兜底**：首领如果被传走超过 25 m，或者掉出场地，就拉回场地中心，并记录下来，作为下次补点的依据。探测 mod 生成首领后会监视 3 分钟，记录“消失”“瞬移”“高度异常”这几种情况。
4. 左殇的屋顶（`BP_ZuoShang_House`）只在序章用到（GEx_01，序章屋顶劈砍），非原址时屏蔽这个技能。

**实测（第 11 轮，登顶山道）**：祈术·火和玉簪放技能时被传到 **(0,0,0)**，隐藏后掉出世界死亡，证实了上面的推断，补点必须做。彭猛、左殇、舞玄没有出现异常。独眼弓手在庞镇（原址附近）正常。白赤练 P2、晏千岁还没测到。

**铃铛线索**：F5 发现铃铛有一个专门的类 `BP_MelodiousBell_Flow_C`（例：溪谷 `NLES_017`），推测就是“由流程触发出现”的铃铛，例如首领战后出现的那些。铃铛实体上的 `FlowTagMap` 全是同一个默认值，没有区分度。世界分区地图一次只加载附近几个铃铛。

**离线扫描结论（第 11 轮后）**：
- 全部 80,974 个地图单元里都找不到 `BP_MelodiousBell_Flow` 的实例。全部 4 万个逻辑资源里，只有 `BellFlow_HasTag` 节点引用了它，所以这个类的铃铛很可能是运行时由流程生成的。
- 首领铃铛流程图（`BPF_Bell_HengDaoKe`、`BPF_Wushi_Bell` 等）的节点是 `SetVisibility`、`CallOwnerFunction RefreshBell`、`ActivateBellAndInteractNoAnim`。也就是说，这些流程图挂在铃铛**自己身上**：首领死前铃铛隐藏，首领死后显示并点亮。流程图里不写铃铛编号，地图单元里也不按名字引用这些流程图，所以离线没法一一对上。
- 187 个铃铛里有 30 个在地图单元里找不到编号，其中既有普通铃铛也有石鹤铃铛，不能当作判断依据。另外数据表编号和实体编号可能不一致：例如 `JJYBP_005` 横刀平台的坐标，正好是实体 `Bell_DDSD_005` 的位置。
- **确认方法**：F5 现在会输出每个铃铛身上挂的流程图名字（`flow:组件=BPF_xxx_Bell`）。传送到候选铃铛后按一次 F5，就能确定对应关系。

### 5.3 首领数值：随境成长

**原作机制**（离线解析得到）
- 怪物的数值 = 基础值 × 等级曲线。曲线是 `CV_AttributeCurve_Monster_Health / Attack / Shachi / ShachiAttack / Infliction`；属性集里有对应的 `Level`、`Health_Max_Lv`、`Attack_Lv` 等字段。
- 等级由所在区域决定，见 `DT_AIAreaLevel`：

| 区域 | 等级 |
|---|---|
| 溪谷 A–D | 1–4 |
| 伏羁之林 A–C | 4–6 |
| 陆家村 A–C | 7–9 |
| 庞镇 A–C | 10–12 |
| 后街 A–C | 13–15 |
| 美谷湖 | 18–20 |
| 正道大营 A–B | 19–20 |
| 甲龙山 | 22 |
| 戏梦山庄 | 22–24 |
| 幻术师遗迹 | 23 |
| 血色森林 | 24 |
| 断魂山 | 25 |

- mod 直接生成的首领不经过区域，所以等级是固定的。实测彭猛在溪谷和庞镇都是 8000 血，所以早期首领在后期会显得太弱，晚期首领在早期又不对劲。

**设计**
- **目标等级 = max(原生等级, 进度等级) + 难度偏移**
  - 原生等级：首领原战场所在区域的等级。
  - 进度等级：玩家已激活铃铛所在区域里的最高等级。也就是说，早期首领会被拉到玩家当前的水平，晚期首领保持原样。
- **难度偏移**（沿用原作的难度名）：入阵者 +0，破局者 +3，逆天者 +6。
- **连战**：整组按组内最高的原生等级和进度等级取大。
- **试炼**：从进度等级 −2 开始，每过一场 +1，上限为进度等级 +6；「凶煞」节点再额外 +2。
- **原貌**（设置里的开关，默认关）：不做提升，按原生等级打，给想体验原汁原味的玩家。
- **实现方式**（第 11 轮实测后定）：
  - mod 生成的首领 `Level = 0`，拿到的是**纯基础值**（彭猛 8000 血 / 120 攻，左殇 8000 / 300，独眼 8000 / 100）。曲线在 0 级取值为 0，所以等级效果完全没有生效，比溪谷 1 级的小怪还“裸”。这就是“前期后期都偏弱”的根源。
  - 直接写 `Level` **不会**重算数值（F10：Level 0→10，血量攻击不变）。
  - 直接乘属性**有效且稳定**（F11：血 ×2、攻 ×1.5，10 秒后仍保持）。
  - 所以采用：按目标等级查游戏自己的曲线，算出倍率后直接写 `Health_Max` / `Health` / `Attack` / `Shachi_Max` / `ShachiAttack` / `Infliction_Max`。曲线和基础值的组合方式（推测是 基础值 ×(1 + 曲线值)）还要用 F9 对照原生小怪确认。
  - 玩家自身的属性一概不动（调试用的无敌模式除外）。
- 曲线采样（等级 1/5/10/15/20/25/30）：血 0.38/2.03/5.07/8.87/11.8/17.5/18.5；攻 0/0.11/0.30/0.65/1.31/1.92/2.02；杀气 0.23/0.95/2.41/3.63/8.75/11.8/12.3。

**HUD**
- 战斗中屏幕上方显示一小行文字：`连战·组织高手 3/5 · 04:12`。用游戏自带的文本样式（`UI/Foundation/Text/Textstyle`）。
- 首领血条使用游戏原生的。

## 6. 多语言

- 跟随游戏当前语言：运行时调用 `KismetInternationalizationLibrary.GetCurrentLanguage()`。
  - `zh-Hans`、`zh-CN` 等 → 简体中文
  - 其他所有语言 → English
  - `zh-Hant` 等 → 繁体中文（已定）。用从游戏简繁对照文本中提取的转换表，在构建时生成，不在运行时转换。
- 所有字符串放在 `lang/zh.lua` 和 `lang/en.lua` 两张表里，用同一个键，缺词时回退到 English。以后加语言只需要再加一个文件。
- **首领名不用自己翻译**：运行时读取游戏的图鉴数据表 `DT_CodexEnemyDataTable` 里的 FText，自动跟随游戏语言。所有游戏支持的语言都会显示正确的首领名。
- 难度名同样直接用游戏的本地化文本（入阵者 / 破局者 / 逆天者）。

关闭方式：它不是可激活控件，不会自己处理按键，所以由 mod 轮询按键来关闭（见下）。

**已实现（`settle.lua`）**：按截图定的版式填入——
- 大标题：「残影尽散」（胜）/「饮恨」（败）/「收刃离去」（放弃），用原作的大字标题格。
- 第一行（居中）：用时；第二行：最佳 | 场地；第三行：击败 n / N。
- 小字行：模式和对象，例如「连战 · 三面」「单挑 · 斧老大：彭猛」，破纪录时后面加「新纪录！」。
- 底部条：「自里武林醒转，回到铃铛之侧。」
- 按确认键关闭（手柄 A / B、回车、空格、鼠标左键；不用 Esc / Start，免得同时打开游戏菜单），否则 20 秒后自动关闭（`config.settle_seconds`），随后传回出发的铃铛。实现方式：每 0.05 秒查询 `PlayerController.IsInputKeyDown`，显示后先等 1 秒，并要求先松开再按下，避免打出最后一击时还按着键就直接关掉。落败时等游戏复活玩家后再显示。若界面创建失败，退回用提示条显示结果。
- 行首的图标格原本是空白方块，先隐藏；以后可以换成原作结算图标（`UI/UINew/Hud/Complete_UI_Art/` 下的计时、死亡、宝物等）。

## 11. 依赖场地的首领：原址专属（0.1.3 起）

**用户决定**：技能依赖原关卡场景物件的首领，固定在原场地打，**只进单挑**，不进连战和试炼；单挑列表里名字后标「· 原址」。

**定位方法**
1. 离线：在全部 8 万个世界分区单元里找首领技能要用的辅助点（中心点、吸附点、召唤点、梅花桩等）所在的单元（`src/tools/origin_arenas.py` 的数据来源）。
2. 游戏内：探测 mod 的 F3 读出这些单元的范围（运行时每张地图的全部单元都在内存里，含未加载的），得到辅助点的大致位置（`src/data/anchor_cells_round1.tsv` 与第二轮结果）。
3. 运行时：传送到离辅助点最近的地表铃铛 → 在已加载的场景里按类名找辅助点（世界分区按 XY 加载，所以里武林空间的也能找到）→ 把玩家放到辅助点上，首领在前方 8 米生成 → 12 秒找不到就提示「原址已不可进入」并传回。
